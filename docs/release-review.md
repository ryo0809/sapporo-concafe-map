## 公開前の必須作業

1. ドメイン所有・DNS・Cloudflareカスタムドメイン・HTTPS・www転送を実環境で確認する。コード内の設定だけでは取得・紐付け完了とは判断できない。
2. 別々のstaging / production D1を用意し、ゼロUUIDの `database_id` を実値へ変更する。マイグレーション0001〜0008を適用し、最新ローカル店舗データを空のstaging DBへ同期・照合してから本番へ進む。
3. 本番管理者を固有の強いパスワードで設定する。初期パスワードのままではstaging / productionのログインを拒否する設計。ローカルの管理者・セッションは本番へ同期しない。
4. GitHub Environment保護、Cloudflare Secrets、バックアップ公開鍵と秘密鍵の保管先、手動デプロイ許可を設定する。公開時のみ `SITE_INDEXABLE=true` とする。
5. stagingでHTTPS上のログイン・Cookie・問い合わせ受付・店舗編集・予約公開を確認する。バックアップからの復元と通知を実際に試す。ローカルテストだけでは実環境の設定を保証できない。
6. 公開する店舗を選定し、実在店舗の情報と地図位置を確認する。テストの店舗情報や問い合わせを本番へ移さない。
7. エラー・停止・使用量の監視通知、定期バックアップ / 復旧、問い合わせの確認頻度と担当者・返信・不要な個人情報の削除運用を決める。問い合わせのメール通知や自動返信は未実装。

現状の `npm run release:check` は本番D1 ID未設定・インデックス公開設定未指定により停止します。これは公開防止のための想定動作です。

## 追加の改善候補

- **開発依存の警告追跡**：`eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces` に、深くネストしたパターンによるDoSの警告。npmは依存関係を含めhighを5件と表示するが、起点はbracesの1件。本番依存監査には含まれず、当アプリでは公開フォームの入力をESLintのglobへ渡していない。現在、[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)に修正版の記載はない。信頼できないglobをビルドへ渡さず、対応版公開後に更新・再監査する。Next.js 14への自動ダウングレードは行わない。
- **問い合わせのページ送り**：現在は状態ごとに新しい順100件まで。件数が増える前にページ送り・検索を追加すると管理しやすい。
- **問い合わせの新着通知**：現在は管理画面で確認する方式。見落としを防ぐにはメール等の通知を追加する。自動返信とは別に設計する。
- **迷惑送信への追加対策**：現在はハニーポットと接続元ごとの1時間5回制限。実際の迷惑送信状況に応じてTurnstile等を検討する。

最新CIの成功とレビュー承認を確認した後に、Issue #5の外部設定・公開手順へ進みます。
